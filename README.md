# tutoring

Платформа репетитора по школьной химии: многоразовая библиотека теории и Заданий по Темам и сборка материалов к занятиям — теории, Заданий, ДЗ, дополнительной практики и Решений. Подходит для изучения школьной программы без сдачи экзамена и для ОГЭ/ЕГЭ. Название сборника не ограничивает использование его содержания.

## Цели

По убыванию приоритета:

1. **Польза на занятиях** — готовиться к занятиям быстро и системно.
2. **Открытый инструмент** — в перспективе им смогут пользоваться другие преподаватели: сначала как кодом, который запускают у себя со своим содержанием, а затем, возможно, как веб-сервисом.
3. **Образец работы с агентами** — система, которая учится на своих ошибках и постепенно автоматизируется; проект показывает это умение в портфолио.

При конфликте целей сначала делаем то, что нужно к ближайшему занятию; технологию берём, только когда она решает настоящую проблему подготовки. Мерило успеха — проверенный автором Комплект к занятию.

## Куда идём

Целевая картина: автор пишет «новый ученик, 9 класс, занятие во вторник в 14:00» — система предлагает план и готовит Комплект; после занятия автор пишет короткий отчёт — система решает, что повторить и какую Тему дать дальше, напоминает о занятиях и материалах. Автор только подтверждает.

Шаги, по порядку:

1. Машина содержания: реестр источников → полная база теории и Заданий по Теме → Конспект → подборка → Комплект.
2. Карта курса: все Темы, порядок, зависимости, заявки на фото Заданий.
3. Ученики: карточка, отчёт после занятия, прогресс по Темам.
4. Планировщик: «новый ученик» → план, «отчёт» → следующий Комплект.
5. Напоминания и расписание.
6. Больше автономии агентов — по мере доверия.

## Что не входит в проект

- Workflow для других областей (встречи, отчёты для клиентов) — отдельные проекты.

## Локальное хранилище chemistry

| Путь | Назначение |
|---|---|
| `tutoring/` | Публичный Git-репозиторий: код, программные `tests/`, документация, ADR и скиллы |
| `tutoring-content/` | Приватный Git-репозиторий: `analysis/` — разборы, `notes/` — Конспекты, `exercises/` — банк, `kits/` — подборки, `tests/` — проверки для ученика |
| `tutoring-sources/` | Оригиналы вне Git: `books/`, `photos/`, `fipi/`, `references/`; состав и охват — в реестре источников |
| `.worktrees/<issue>/` | Только временная пара рабочих копий; удаляется после подтверждённой доставки |
| `tutoring-content/build/` | Исключённые из Git производные PDF существующего сборщика |
| `Занятия/` | Будущая выдача двух PDF по lesson-output.md; создаётся реализацией #9, пока отсутствует |

Учёт учеников — отдельное будущее расширение; обязательного каталога учеников сейчас нет. Приватные данные не включаются в репозитории. Удалённая 16.11.2026 заготовка не содержала данных ученика.

Исторические разборы и `analysis/archive/` не заменяют текущие правила и подтверждения охвата. Для подготовки новой Темы сначала сверяются карта, реестр и issue. Существующие `kits/oge/` сохраняют свои пути; школьное применение не требует их миграции. Школьный вариант нового формата должен поддерживаться в #9.

По подтверждению автора электронные книги имеют резервные копии. Для фотографий отдельное резервное копирование автор не требует; исходные фотографии сохраняются, а Git-репозитории и папка выдачи не являются их резервной копией. Это ограничение хранения, не автоматическая функция проекта.

## Сборка PDF

Ниже описан существующий сборщик. Новый формат из `docs/lesson-output.md` ещё не реализован; старые Комплекты сохраняют прежний вывод.

Нужны Python 3.9+, Google Chrome (печатает HTML в PDF) и интернет (формулы KaTeX и шрифт грузятся из сети). Путь к Chrome в `tools/build_kit.py` записан под macOS.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/build_kit.py ../tutoring-content kits/oge/basic-concepts-1/kit.md
.venv/bin/python tools/build_kit.py ../tutoring-content tests/level-test-9.md
```

В `tutoring-content/build/` попадают только PDF. Комплект — в `build/oge/<NN>-<id Темы>-<N>/`: «Тема 2.1 — занятие.pdf», «— решения.pdf», «— преподавателю.pdf» и, если у Комплекта есть `entry_check`, «— входная проверка.pdf» (слайды 16:9 по ДЗ этого Комплекта, проводятся в начале следующего занятия). Тест — в `build/tests/<название>.pdf`. В `theory_block` можно выбрать Разделы: `notes/basic-concepts.md#4,6-8`; Разделы с пометкой `<!-- exams: ЕГЭ -->` в Комплект ОГЭ не попадают.

Сборщик проверяет выбор и перенумерацию Разделов. Полный валидатор файлов Заданий (#4) и проверка баланса уравнений (#17) пока не реализованы. Пока агент выполняет содержательные проверки отдельно. Историческое поле `spare` не выводится сборщиком; прежнее требование скрытых запасных Заданий заменено общей дополнительной практикой в новых Комплектах. Для них сначала нужна доработка сборщика (#9) под согласованные требования.
